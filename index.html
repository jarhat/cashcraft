Fungible tokens are interchangeable units of the same category, like identical coins.

An NFT is a non-fungible token. It can carry application-defined data and a capability.

BCMR describes token metadata such as names and icons. It does not prove a token is authentic.

      

      
A practical guide to Bitcoin Cash tokens. This overview is not a consensus implementation; consult the CashTokens specification ↗ and its test vectors for normative rules.

      
UTXOs and categories
        
CashTokens are consensus-validated data on BCH outputs, not a separate ledger. An output contains satoshis, locking bytecode and optionally one token category, with fungible units, one NFT, or both. BCH pays transaction fees.

        
A category is identified by 32 bytes. Genesis is associated with spending output index 0 of an earlier transaction; that transaction's hash identifies the eligible category. Displayed IDs and wire bytes may use different byte order. Names and logos do not establish identity.

      

      
Fungible amounts and burns
        
Amounts are integer base units. An encoded amount must be positive and no greater than 263 − 1. Decimal places are metadata, not consensus.

        
For an existing category, outputs cannot exceed inputs. The difference is burned; genesis is the issuance exception. For example, 100 input units and 90 output units burn 10. Token-unaware spending can accidentally destroy tokens.

      

      
NFTs, commitments and capabilities
        
An NFT has a category, a capability and an application-defined commitment of up to 40 bytes. A commitment need not be unique or prove authenticity.

        
None (immutable): ordinary continuation preserves the commitment. Mutable: a valid successor can change it. Minting: an input with minting authority can authorize new NFTs in its category. Whether authority is safe depends on who can spend it and on any covenant restrictions.

        
Validation accounts for all NFTs and authority in a category across the transaction; it is not a simple one-input-to-one-output rule. This wallet's advanced inspector is read-only and shows only scanned wallet outputs, not all authority in the category.

      

      
Encoding and validation
        
The token prefix encodes the category, a bitfield and optional commitment and amount. Invalid combinations, reserved capabilities, non-minimal encodings, zero encoded amounts and out-of-range values are rejected. Use the complete CHIP algorithm and test vectors for duplicate NFTs, mutable transitions, minting and genesis.

      

      
Script, covenants and signing
        
Token introspection lets BCH Script examine token data on inputs and outputs. A covenant can impose additional rules on destinations, amounts or state transitions; consensus validity alone does not establish an application's policy.

        
Token-aware signing must account for the assets and relevant transaction data. The specification includes signing-serialization changes such as SIGHASH_UTXOS. Always review the transaction in a token-aware wallet before signing.

      

      
Metadata, supply and trust
        
BCMR metadata can supply names, symbols, decimals, descriptions and icons, but these are not the consensus category ID and are not proof of an issuer's claims. Similar names can refer to different categories.

        
Supply figures depend on how extant, reserved and circulating units are defined. A minting NFT is authority to create NFTs, not fungible supply already issued. Consensus validity does not prove backing, redemption or value.

      

      
History and checklist
        
CashTokens are a consensus-level descendant of colored-coin ideas. Unlike application-layer conventions such as SLP, their core token rules are enforced by network nodes; indexers remain useful for discovery and presentation.

        
Check the exact category and genesis, current UTXOs, minting authority and its controller, NFT capability and commitment, covenant rules, metadata authenticity, wallet token handling, conformance tests and any economic claims independently.

      

      
FAQ
        
Why do I need BCH? Token-bearing outputs hold satoshis, and transaction fees are paid in BCH.

        
Does a minting NFT create fungible units? No. It authorizes NFT issuance in its category, not ordinary fungible inflation.

        
Does this inspector show every minting authority? No. It describes only NFTs found in the scanned wallet addresses.

        
Can I trust a token's name or icon? Not on its own. Check the exact category and independently verify issuer claims and controlling scripts.
